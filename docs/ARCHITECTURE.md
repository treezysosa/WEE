# Architecture
C++20 / JUCE 8.0.6 / CMake, Windows VST3 instrument and standalone. Development order: Phases 1–2 cover composition, instruments, layers, state and MIDI; Phase 3 adds effects and audio rendering. Phases 4–5 cover advanced composition, presets/editing/history and production polish/performance/host verification.

Music/Composition.h: portable deterministic LCG generator, shared key/scale/progression and eight musical roles. Instruments/Piano.h: sixteen polyphonic additive/FM voices per layer, eight synthetic timbres. PluginProcessor: host PPQ/tempo scheduler, stereo mixer, 20 ms gain/pan smoothing, APVTS parameters, lock-preserving generation and versioned exact note state. Old project states migrate without replacing their saved melody. Note-offs precede note-ons at shared event times.

Effects/EffectChain.h: portable preallocated stereo effect chain and parameter ramps. Effects/Flip.h: real offline reverse/half-speed/granular transpose and boundary conditioning. Effects/Parameters.h: appended stable parameter IDs used by both layout and controls. Master effects run in the processor after the layer mix. Cached sample audition replaces that output before the live master gain.

Export/Midi.h: format 0 per layer, format 1 named/channel-separated layers plus conductor track, 960 PPQ and exact nominal end. Export/Wav.h: portable little-endian RIFF PCM16/24 and IEEE float32 writer with fact chunk and cancellation checks. Export/Renderer.cpp: a cloned processor driven by a deterministic offline playhead, warm-up/capture/tails, FLIP DSP and worker-thread file exports. Jobs use snapshots and never modify live notes. Writes use native filesystem paths for Unicode Windows directories.

UI has Create/Mixer and FX/FLIP/WAV pages in scrollable viewports. A background job belongs to the editor and cancels/joins before processor removal; published audition audio belongs to the processor. Audio uses a non-blocking try-lock while reading its cache; old buffers are freed by the publisher, outside that lock and outside audio processing. A change token invalidates stale snapshots. Master volume is excluded because cached audio is stored at unity master gain.

State version 4 stores all parameters, context, next generation seed, every layer's notes/seeds and lossless timing bits. Missing older parameters get defaults. Bounded processor-owned undo/redo snapshots are stored in a separate History child as base64 content-state blobs, never recursively. Up to eight snapshots and 2 MiB are retained per direction. Offline rendering and presets use content-only snapshots. Rendered audition buffers remain ephemeral. Exported WAVs persist on disk. UI/PianoRoll.h drafts gestures off the audio thread; PluginProcessor validates and commits complete layers while preserving locks and rejecting stale gesture content. Presets/Factory.h describes six original factory arrangements. Local .wee files contain versioned generated content and parameters; explicit loading records the previous content as an undo transaction.

See PHASE-2.md / PHASE-3.md for lock rules, granular half-time semantics, export limits and real-time limitations. Automated checks do not establish FL Studio compatibility.
